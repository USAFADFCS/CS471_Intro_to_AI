**1. Search Problem Formulation**

Define the four components of this search problem.
* A state space must include the grid location AND the status of the two supply caches.
* It has four states, x, y, and a status of cache 1 & cache 2.
* The valid movements are: North, South, East, West.
* The team must be at the extraction zone (9, 9) AND both caches must be collected.
* Standard movement costs 1.0 per grid movement.

<details>

**Answer:**

* State Space: (x, y, boolean, boolean)

* Actions: N, S, E, W

* Goal Test: (9, 9, True, True)

* Path Cost: 1.0 per step

**2. State Space Size**

What is total size of the state space if the grid is 10x10?

<details>
  <summary>Show solution</summary>

**Step 1:** Calculate the base positional locations. A 10x10 grid has $10 \times 10 = 100$ locations.

**Step 2:** Calculate the boolean modifiers. There are two caches, meaning there are $2^2 = 4$ possible combinations of having collected them (Neither, Cache 1 only, Cache 2 only, Both).

**Step 3:** Multiply the independent variables to find the total state space size. $100 \times 4$.

**Answer:**
The total size of the state space is 400 distinct states.

**3. Trees and State Space**

If the agent starts at (1,1) and moves North to (1,2), and then South back to (1,1), does this create a new node in the Search Tree?


<details>
  <summary>Show solution</summary>

**Step 1:** Understand the properties of a State Space Graph. In the graph, (1,1) exists only exactly once.

**Step 2:** Understand the properties of a Search Tree. In a search tree, a node represents the entire history of the path taken.

**Step 3:** Compare the paths.
* Path 1: Start at (1,1).
* Path 2: Start at (1,1) -> Go North (1,2) -> Go South (1,1).
These are two distinct plans/histories.

**Answer:**
Yes. Even though the physical state is identical, it creates a brand new Node in the Search Tree because the tree represents "plans," and the path taken to arrive there was different. This highlights why Search Trees suffer from massive repeated structure.

</details>
