**1. The Policy Evaluation Calculation**

An autonomous reconnaissance drone is currently in the state $S_{recon}$. It has been handed a fixed playbook (policy) $\pi_0$ that says: *"Always Loiter."* Your job is to evaluate how good this policy actually is — **not** to search for a better one yet.

You are given the following environmental dynamics and current value estimates ($V_k$) for the surrounding states. The discount factor is $\gamma = 0.5$.

*   **Current State Values ($V_k$):**
    *   $V_k(S_{recon}) = 2$
    *   $V_k(S_{target}) = 20$
    *   $V_k(S_{danger}) = -10$

*   **Policy $\pi_0(S_{recon})$ = Loiter**
    *   100% probability ($T=1.0$) of remaining in $S_{recon}$.
    *   Immediate reward: $+1$.

Calculate $V_{k+1}^{\pi_0}(S_{recon})$ using the Policy Evaluation update. Remember: Policy Evaluation only ever computes the value of the action the policy dictates — there is no $\max_a$ operator involved.

<details>
  <summary>Show solution</summary>

  **Step 1:** Because the policy is fixed to Loiter, we only compute the expected value of *that one action* — we do not consider Advance at all.

  $$V_{k+1}^{\pi_0}(S_{recon}) = \sum_{s'} T(s, \pi_0(s), s')[R(s,\pi_0(s),s') + \gamma V_k(s')]$$

  * $V_{k+1}^{\pi_0}(S_{recon}) = 1.0 \times [1 + 0.5(2)]$
  * $V_{k+1}^{\pi_0}(S_{recon}) = 1.0 \times [1 + 1] = 2$

  **Answer:**

  $V_{k+1}^{\pi_0}(S_{recon}) = \mathbf{2}$. Notice this is a much cheaper calculation than a Value Iteration backup — we never had to touch the Advance branch at all, because the policy already told us which action to take.

</details>

**2. Policy Extraction and Improvement**

Using the value you just calculated, $V^{\pi_0}(S_{recon}) = 2$, the drone's controller now wants to check whether $\pi_0$ ("Always Loiter") is actually the best playbook available, or whether it should be improved.

Recall the same environmental dynamics from Question 1: Advance has an 80% chance ($T=0.8$) of reaching $S_{target}$ (reward $+10$) and a 20% chance ($T=0.2$) of drifting into $S_{danger}$ (reward $-5$), with $V_k(S_{target}) = 20$, $V_k(S_{danger}) = -10$, and $\gamma = 0.5$.

Perform **Policy Extraction**: compute the Q-value of both actions at $S_{recon}$ and determine the new policy $\pi_1(S_{recon})$.

<details>
  <summary>Show solution</summary>

  **Step 1:** Compute $Q(\text{Loiter})$. This is just the value we already found in Question 1:

  * $Q(\text{Loiter}) = 1.0 \times [1 + 0.5(2)] = 2$

  **Step 2:** Compute $Q(\text{Advance})$ using a one-step lookahead:

  * Target Outcome: $0.8 \times [10 + 0.5(20)] = 0.8 \times 20 = 16$
  * Danger Outcome: $0.2 \times [-5 + 0.5(-10)] = 0.2 \times (-10) = -2$
  * $Q(\text{Advance}) = 16 + (-2) = 14$

  **Step 3:** Apply $\arg\max_a$ to select the new policy:

  * $\pi_1(S_{recon}) = \arg\max(Q(\text{Loiter})=2,\ Q(\text{Advance})=14) = \text{Advance}$

  **Answer:**

  $\pi_1(S_{recon}) = \mathbf{Advance}$. Since $\pi_1 \neq \pi_0$, the policy has changed — Policy Iteration is **not** done yet. The algorithm would now loop back to Policy Evaluation, this time evaluating $\pi_1$ ("Always Advance") to completion, before extracting again to check for stability.

</details>

**3. The Cost Trade-off of Policy Iteration**

A junior AI engineer reviews both the Value Iteration and Policy Iteration deployment code and concludes that Policy Iteration must simply be the "better" algorithm, since it usually reaches the optimal answer in far fewer outer iterations.

Explain why this conclusion is misleading. Why is each outer iteration of Policy Iteration typically more computationally expensive than a single sweep of Value Iteration, and under what condition are the two algorithms guaranteed to produce the exact same final answer?

<details>
  <summary>Show solution</summary>

  **Step 1:** Identify what happens *inside* a single outer iteration of each algorithm.<br>
  **Step 2:** Compare that cost to what the "fewer iterations" claim is actually measuring.

  **Answer:**

  The engineer is comparing the wrong unit of work. A single Value Iteration sweep performs one Bellman backup per state, using the $\max_a$ operator once, and moves on. A single outer iteration of Policy Iteration, by contrast, requires running the **entire Policy Evaluation loop to convergence** — potentially many sweeps — before a single Policy Extraction step is even attempted. So while Policy Iteration usually needs far fewer *outer* iterations, each of those iterations does substantially more internal work.

  Both algorithms are guaranteed to converge to the exact same optimal value function $V^*$ and optimal policy $\pi^*$, because any MDP with a well-defined discount factor has a unique optimal value function. Value Iteration converges to it asymptotically as $k \to \infty$ (or in practice, once values stop changing meaningfully), while Policy Iteration converges to it exactly and provably the moment the extracted policy stops changing. The two algorithms simply take different computational paths to the same destination.

</details>
