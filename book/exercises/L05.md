# L5: Uninformed Search

**1. Depth-First Search** 

```{mermaid}
graph TD
    S((S)) --> A((Sector A))
    S --> B((Sector B))
    A --> C((Sector C))
    A --> D((Sector D))
    C --> E((Sector E))
    C --> F((Sector F))
    B --> G((Goal))
    
    style G fill:transparent,stroke:#2ecc71,stroke-width:3px
```

Based on the graph above, list the exact sequence of nodes the drone will expand (evaluate) before it successfully finds the Goal. What property of DFS does this massive detour demonstrate?


<details>
  <summary>Show solution</summary>

**Step 1:** Identify the algorithm's Frontier management. DFS uses a LIFO (Last-In, First-Out) Stack. It plunges as deeply as possible down the left-most (or first alphabetical) path until it hits a dead end.

**Step 2:** Trace the expansion order step-by-step.

* Expand S. Add A, B to stack. (Top of stack is A).

* Expand A. Add C, D to stack. (Top is C).

* Expand C. Add E, F to stack. (Top is E).

* Expand E. Dead end.

* Expand F. Dead end.

* Expand D. Dead end.

* Finally retreat to S's other branch and Expand B.

* Expand G (Goal found).

**Step 3:** Analyze the behavior. The Goal was only 2 steps away (Depth 2), but the drone evaluated nodes at Depth 3 (E, F) before ever checking Sector B.

**Answer:**

The exact expansion sequence is: S, A, C, E, F, D, B, G.
This demonstrates that DFS is not optimal. It blindly commits to a deep path and ignores a shallow, easily accessible goal just because of its position in the search tree.

**2. Breadth-First Search**

```{mermaid}
graph TD
    S((S)) -- "10 Fuel" --> A((Waypoint A))
    S -- "1 Fuel" --> B((Waypoint B))
    A -- "10 Fuel" --> G((Goal))
    B -- "1 Fuel" --> C((Waypoint C))
    C -- "1 Fuel" --> D((Waypoint D))
    D -- "1 Fuel" --> G
    
    style G fill:transparent,stroke:#2ecc71,stroke-width:3px
```

Which exact path will the BFS algorithm select? Calculate the fuel cost of the BFS path, and contrast it with the true optimal path.


<details>
  <summary>Show solution</summary>

**Step 1:** Identify how BFS evaluates paths. BFS uses a FIFO (First-In, First-Out) Queue. It explores tier-by-tier, meaning it strictly evaluates paths based on the number of steps (depth), completely ignoring the edge weights (fuel costs).

**Step 2:** Trace the BFS tiers.

* Tier 1: Waypoints A and B (1 step away).

* Tier 2: Goal (via A) and Waypoint C (2 steps away).

* BFS finds the Goal on Tier 2 and stops searching.

**Step 3:** Calculate the path costs.

BFS Path: S -> A -> G. Cost = 10 + 10 = 20 Fuel.

Alternate Path: S -> B -> C -> D -> G. Cost = 1 + 1 + 1 + 1 = 4 Fuel.

**Answer:**
BFS will select path S -> A -> G because it is the shallowest solution (only 2 steps). This will cost 20 Fuel. This proves that BFS is not optimal when path costs vary; it missed the much cheaper 4 Fuel path simply because it required more physical steps.


</details>

**3. Uniform Cost Search**

```{mermaid}
graph LR
    S((S)) -- 2 --> A((A))
    S -- 5 --> B((B))
    A -- 1 --> C((C))
    A -- 6 --> G((G))
    C -- 1 --> B
    B -- 2 --> G
    
    style G fill:transparent,stroke:#2ecc71,stroke-width:3px
```

Trace the exact contents of the Priority Queue (the Fringe) during the search. List the order in which the nodes are expanded, and state the final optimal path and its cumulative cost.


<details>
  <summary>Show solution</summary>

**Step 1:** Identify UCS Frontier management. UCS uses a Priority Queue, always expanding the node with the lowest cumulative path cost from S.

**Step 2:** Trace the expansions and queue updates.

* Start: Add S to PQ. [S(0)]

* Expand S: Add A and B. PQ = [A(2), B(5)]

* Expand A (Lowest is 2): Add C(2+1=3) and G(2+6=8). PQ = [C(3), B(5), G(8)]

* Expand C (Lowest is 3): Add B(3+1=4). We now have two paths to B. The cheaper one takes priority. PQ = [B(4), B(5), G(8)]

* Expand B (Lowest is 4, via S-A-C-B): Add G(4+2=6). PQ = [G(6), G(8)]

* Expand G (Lowest is 6): Goal test passed!

**Step 3:** Extract the final path history for the winning node.

**Answer:**

The exact expansion order is: S, A, C, B, G.
The final optimal path is S -> A -> C -> B -> G, with a total cumulative cost of 6.
Notice how UCS successfully ignored the direct S -> B and A -> G links in favor of chaining multiple smaller, cheaper movements together.

</details>
