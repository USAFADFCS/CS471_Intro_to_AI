```{mermaid}

    S -- "Fuel: 2" --> B((Sector B<br>h=8))

    B -- "Fuel: 3" --> C((Sector C<br>h=3))

```

Based on the tactical graph above, trace the exact path the Greedy Best-First Search agent will select to reach the Goal. Calculate the total fuel cost and explain why the agent made this suboptimal choice.

<details>
  <summary>Show solution</summary>

**Step 1:** Identify the algorithm's evaluation function. Greedy Search strictly uses $f(n) = h(n)$. It looks exclusively at the estimated heuristic distance to the goal and completely ignores the actual fuel costs ($g(n)$) across the edges.

**Step 2:** Trace the expansion order step-by-step.
* Start at S. The agent evaluates its neighbors: Sector A ($h=4$) and Sector B ($h=8$).
* Expand A (Lowest $h$).
* From Sector A, the only available path is to G ($h=0$).
* Expand G (Goal found).

**Step 3:** Analyze the behavior and cost.
* Greedy Path: S -> A -> G.
* Cumulative Cost: $1 + 12 = 13$ Fuel.
* Alternate (Optimal) Path: S -> B -> C -> G. Cost: $2 + 3 + 2 = 7$ Fuel.

**Answer:**

The exact path selected is: S -> A -> G, costing 13 Fuel.
The agent fell into a tactical trap because it only looked at the heuristic. Sector A appeared closer to the goal ($h=4$) than Sector B ($h=8$), so it greedily committed to Sector A, blinding itself to the massive edge cost of 12 required to actually reach the target from that position.

**2. A* Search: Balancing Cost and Estimation**

```{mermaid}
graph LR
    S((Start<br>h=15)) -- "Fuel: 1" --> A((Sector A<br>h=4))
    S -- "Fuel: 2" --> B((Sector B<br>h=8))
    A -- "Fuel: 12" --> G((Goal<br>h=0))
    B -- "Fuel: 3" --> C((Sector C<br>h=3))
    C -- "Fuel: 2" --> G

    classDef default fill:#f9f9f9,stroke:#888,stroke-width:2px,color:#000;
    classDef goal fill:transparent,stroke:#2ecc71,stroke-width:3px,color:#000;
    linkStyle default stroke:#a0a0a0,stroke-width:2px;
    class G goal;
```

Using the exact same graph, trace the contents of the Priority Queue (the Fringe) using the A* Search algorithm. List the order in which the nodes are expanded, state the final optimal path, and prove how A* corrects the Greedy algorithm's mistake.

<details>
  <summary>Show solution</summary>

**Step 1:** Identify the A* evaluation function: $f(n) = g(n) + h(n)$. The Priority Queue (PQ) will always sort and expand the node with the lowest total $f(n)$.

**Step 2:** Trace the expansions and queue updates mathematically.
* Start: Add S to PQ. PQ = [S($f=15$)]
* Expand S: Calculate $f(n)$ for neighbors A and B.
  * Node A: $g(1) + h(4) = 5$
  * Node B: $g(2) + h(8) = 10$
  * PQ = [A($f=5$), B($f=10$)]
* Expand A (Lowest is 5): Calculate $f(n)$ for neighbor G.
  * Node G: $g(1+12) + h(0) = 13$
  * PQ = [B($f=10$), G($f=13$)]
* Expand B (Lowest is 10): Notice how A* dynamically abandons the path to G because its total cost inflated past B's. Calculate neighbor C.
  * Node C: $g(2+3) + h(3) = 8$
  * PQ = [C($f=8$), G($f=13$)]
* Expand C (Lowest is 8): Calculate neighbor G (from C).
  * Node G2: $g(2+3+2) + h(0) = 7$
  * PQ = [G2($f=7$), G($f=13$)]
* Expand G2 (Lowest is 7): Goal test passed!

**Answer:**

The exact expansion order is: S, A, B, C, G.
The final optimal path is S -> B -> C -> G, with a total cumulative cost of 7 Fuel.
A* successfully corrects the Greedy mistake. While it initially explored Sector A (just like Greedy), it tracked the exact cost ($g(n)$). When the path through A became too expensive ($f=13$), A* shifted its attention back to Sector B ($f=10$), successfully discovering the cheaper optimal route.

</details>

**3. Inadmissible Heuristics**

```{mermaid}
graph LR
    S((Start<br>h=10)) -- "Fuel: 3" --> A((Sector A<br>h=15))
    S -- "Fuel: 8" --> B((Sector B<br>h=2))
    A -- "Fuel: 2" --> G((Goal<br>h=0))
    B -- "Fuel: 3" --> G
    
    classDef default fill:#f9f9f9,stroke:#888,stroke-width:2px,color:#000;
    classDef goal fill:transparent,stroke:#2ecc71,stroke-width:3px,color:#000;
    linkStyle default stroke:#a0a0a0,stroke-width:2px;
    class G goal;
```

A field routing agent is using A* to navigate the grid above, but its sensor payload is malfunctioning, resulting in flawed heuristic data. Trace the A* search on this graph. Does the agent find the optimal path? Explain why based on the mathematical properties of the heuristic.

<details>
  <summary>Show solution</summary>

**Step 1:** Trace the A* search using the provided values ($f(n) = g(n) + h(n)$).
* Expand S. Add A and B to PQ.
  * Node A: $g(3) + h(15) = 18$
  * Node B: $g(8) + h(2) = 10$
  * PQ = [B($f=10$), A($f=18$)]
* Expand B (Lowest is 10). Add G to PQ.
  * Node G (via B): $g(8+3) + h(0) = 11$
  * PQ = [G($f=11$), A($f=18$)]
* Expand G. Goal test passed. Path found: S -> B -> G (Cost = 11).

**Step 2:** Compare the A* result against the physical graph.
* A* Output Path: S -> B -> G (Cost = 11).
* True Optimal Path: S -> A -> G (Cost: $3 + 2 = 5$).

**Answer:**

No, the agent completely misses the optimal path.
This occurs because the heuristic for Sector A is inadmissible. An admissible heuristic must never overestimate the true remaining cost to the goal. The true cost from Sector A to the Goal is 2, but the malfunctioning sensor provided a heuristic of $h=15$. This massive overestimation artificially inflated Sector A's mathematical $f(n)$ score to 18, causing the A* algorithm to incorrectly ignore the optimal path and settle for a highly inefficient detour.

</details>
